Features

The memory your agents don't have.

Claude Code transcripts are scattered across laptops and short-lived cloud containers. Scry collects them as they happen, so nothing your team worked out with an agent gets lost.

Search across every session

Press / and search every prompt, answer, thinking block and tool result, across one project or all of them. Click a hit to jump straight to that line in the conversation.

Full-fidelity replay

Read any session as a chat: Markdown answers, collapsible thinking, tool calls with their results, and badges on aborted or errored turns. Cloud sessions link back to claude.ai/code.

Captured as it happens

Prompts are saved the moment they're sent and responses when the turn ends, so a crashed container or interrupted turn never loses the conversation.

Projects keep things apart

Give each team or Claude account its own project. Sessions, search and ingest tokens are all scoped per project.

Scoped ingest tokens

Each project gets its own token, stored only as a hash. A token can write to its own project and nothing else, and rotating it retires the old one instantly.

How it works

Up and running in three steps.

A lightweight Claude Code plugin sends each turn to your Scry server. No SDK, no code changes, no proxy in front of Claude.

Create a project

Open the app and click New project. Scry shows the project's ingest token once. Keep it somewhere safe.

Scry appOpen app
# Project   work
# Token     scry_••••••••••••••••••••••••
# Ingest    https://scry.example.com/ingest

Install the plugin

Add this to your cloud environment's setup script, or install it locally. Scry serves the plugin itself, so there's nothing else to download.

setup script
mkdir -p ~/.claude-plugins && cd ~/.claude-plugins
rm -rf chat-logger claude-chat-logger
curl -fsSL https://scry.example.com/plugin | tar -xz
mv claude-chat-logger chat-logger

Point it at Scry

Set four environment variables, with the token stored as a secret. Every new session logs to Scry from then on.

environment
CLAUDE_CODE_PLUGIN_DIRS=~/.claude-plugins/chat-logger
SCRY_INGEST_URL=https://scry.example.com/ingest
SCRY_PROJECT=work
SCRY_INGEST_TOKEN=scry_…
Desktop app

Scry for your Mac.

The desktop app runs the same server and UI on your own machine, at http://127.0.0.1:9999, and also searches the transcripts Claude Code already keeps in ~/.claude/projects.

Download for Apple Silicon Intel Mac
Apple Silicon (M1 and later) or Intel · macOS 11 or later · Not sure? Apple menu → About This Mac → Chip
  1. Open the DMG and drag Scry into Applications. It doesn't install itself.
  2. Allow it once. Scry isn't notarized by Apple yet, so the first launch is blocked. Open Scry, click Done, then go to System Settings → Privacy & Security, click Open Anyway next to Scry and confirm. Or run this in Terminal, then open it normally:
    Terminal
    xattr -dr com.apple.quarantine /Applications/Scry.app
  3. Point the plugin at it. Create a project in the app, then set SCRY_INGEST_URL=http://scry_public_ip:9999/ingest with that project's token, as in step 3 above.
Self-hosting

Your transcripts never leave your infrastructure.

Agent conversations are full of code, credentials in error messages, and design decisions. Scry runs on your own servers, so they stay yours.

  • One small container. Node with no runtime dependencies, sessions stored as plain JSONL files on a volume.
  • Locked down by default. The app sits behind basic auth; ingest only accepts project tokens.
  • No lock-in. Your data is files you can grep, back up or move. Nothing proprietary.
  • Desktop too. Prefer local? The macOS app runs the same UI and also searches ~/.claude/projects.
FAQ

Questions, answered.

What exactly does Scry capture?

Each user prompt when it's submitted, and each agent response when the turn ends, including streamed thinking and why the turn ended (completed, aborted or errored). Subagent turns are skipped. Raw Claude Code transcript files are understood too.

What happens if the Scry server is down?

The plugin warns once per session and keeps logging to a local file (~/.claude/chat-log.jsonl), so Claude Code keeps working normally.

Can I keep work and personal sessions separate?

Yes. Create a project per Claude account or team and give each its own SCRY_PROJECT and token. A token can only write to its own project, and the app lets you browse one project or all of them.

How do I deploy it?

Run the Docker image with a volume mounted at /data and SCRY_USER / SCRY_PASS set. A Kubernetes manifest with a persistent volume is included, and /healthz is there for probes.

Does Scry slow down Claude Code?

No. The plugin sends one small HTTP request per prompt and per finished turn, outside the model's path.
